Before connecting

1. Create a Supabase project

Copy its Project URL and anon/publishable key from Project Settings → API.

2. Apply the migration

Run the SQL migration in supabase/migrations using the Supabase SQL editor or Supabase CLI. The table uses row-level security and only allows an authenticated owner to access their workspace row.

3. Enable GitHub in Supabase

In Supabase Authentication → Sign In / Providers, enable GitHub and enter a GitHub OAuth App client ID and secret. In GitHub Developer Settings, set the OAuth App callback URL to https://asqszzgunsrdclunbxfq.supabase.co/auth/v1/callback. In Supabase URL Configuration, allow your app URL, currently http://127.0.0.1:8765/. Use your deployed HTTPS origin after deployment.

This first cloud version stores a versioned workspace JSON snapshot in one owner-scoped row. Image bytes in the local asset shelf are excluded from cloud sync; use secure Supabase Storage for those later.

Security boundary

Only the anon/publishable key belongs here. Never use a service-role key, OAuth secret, Discord bot token, or database password in this browser app. RLS is required before any account signs in.

Cloud sync does not encrypt your data before it reaches Supabase. Protect your account, use HTTPS in deployment, and review your provider's retention and privacy settings.
